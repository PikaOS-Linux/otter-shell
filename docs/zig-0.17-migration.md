# Zig 0.17 migration report

Otter Shell now targets Zig 0.17.0. Migration covers application and library sources, build scripts, examples, benchmarks, bundled dependencies, CI toolchains, the website version badge, and Zenith dependency seeding. All 62 Zig package builds and all 61 available package test targets pass. The full 0.12.0 release train includes every source package pinned by Zenith.

The migration follows the [official Zig 0.17 release notes](https://ziglang.org/download/0.17.0/release-notes.html). Existing `zig build -Doptimize=ReleaseFast` commands remain valid; Zig source uses the new `.fast` optimization tag.

## Language and standard library changes

These changes recur across the workspace. Examples are shortened to show the relevant operation.

| Purpose | Before | After |
| --- | --- | --- |
| Enum to integer | `@intFromEnum(value)` | `@backingInt(value)` |
| Integer to enum | `@enumFromInt(raw)` | `@fromBackingInt(@intCast(raw))` |
| Repeated array | `[_]u8{0} ** 64` | `@as([64]u8, @splat(0))` |
| Repeated string | `"x" ** 64` | `&@as([64:0]u8, @splat('x'))` |
| Integer type construction | `std.meta.Int(.unsigned, bits)` | `@Int(.unsigned, bits)` |
| Optimization type and tag | `std.builtin.OptimizeMode`, `.ReleaseFast` | `std.lang.Optimize`, `.fast` |
| Sentinel allocation | `allocator.dupeZ(u8, text)` | `allocator.dupeSentinel(u8, text, 0)` |
| Sentinel formatting | `std.fmt.bufPrintZ(buf, fmt, args)` | `std.fmt.bufPrintSentinel(buf, fmt, args, 0)` |
| Function reflection | `info.@"fn".params[i].type` | `info.@"fn".param_types[i]` |
| Empty static bit set | `.initEmpty()` | `.empty` |
| Linux auxiliary vector key | `std.elf.AT_CLKTCK` | `std.elf.AT.CLKTCK` |

Array changes preserve lengths, UTF-8 bytes, and required sentinels. Browser scratch allocation uses `std.heap.BufferFirstAllocator` with an explicit stack buffer instead of removed `stackFallback`.

## Reflection and generated code

Struct and enum reflection now exposes parallel arrays. Config parsing/serialization, UI registries, plugin ABI checks, image formats, Unicode generators, and the bundled highlighter all needed changes.

Before, in `otter-conf/src/parser.zig`:

```zig
inline for (std.meta.fields(T), 0..) |field, i| {
    if (std.mem.eql(u8, name, field.name)) return i;
}
```

After:

```zig
const fields = @typeInfo(T).@"struct";
inline for (fields.field_names, 0..) |field_name, i| {
    if (std.mem.eql(u8, name, field_name)) return i;
}
```

Loops needing types iterate `field_names` and `field_types` together. Generated struct attributes use `std.lang.Type.Struct.FieldAttributes`; pointer constness uses `pointer.attrs.@"const"`. Code emitted by generators was migrated too.

## C bindings and image representation

FreeType, HarfBuzz, and PipeWire wrappers still contained removed `@cImport` calls. They now translate headers during the build and import the generated module.

Before:

```zig
const c = @cImport({
    @cInclude("ft2build.h");
});
```

After, in the FreeType build wrapper:

```zig
const c = b.addTranslateC(.{
    .root_source_file = b.path("freetype-zig.h"),
    .target = target,
    .optimize = optimize,
});
c.addIncludePath(upstream.path("include"));
module.addImport("c", c.createModule());
```

The wrapper source then uses `@import("c")`. Existing first-party build-time translation remains compatible with 0.17, although Zig now recommends the standalone translate-c package for future migrations.

Zig also rejects `@bitCast` involving extern structs. HarfBuzz features and zigimg color conversions now copy named fields. TGA decoding explicitly reads little-endian bytes.

```zig
// Before: infer a value by reinterpreting an extern struct.
@bitCast(f)

// After: preserve HarfBuzz's four values explicitly.
.{ .tag = f.tag, .value = f.value, .start = f.start, .end = f.end }
```

## Build paths and packaging

Run steps now call `addPassthruArgs()`. Build-root access uses `b.root`; file and directory dependencies are registered with the build graph. Install locations use lazy paths because they are resolved at build execution time.

```zig
// Before
if (b.args) |args| run.addArgs(args);
const staging = b.pathJoin(&.{ b.install_prefix, "package" });

// After
run.addPassthruArgs();
const staging: std.Build.LazyPath = .{ .relative = .{
    .base = .install_prefix,
    .sub_path = "package",
} };
```

This affected Bench package staging, Clip aliases, portal service files/dialog paths, and browser helper pkg-config metadata. Portal paths are generated by `tools/install-paths.py`, with tests for custom prefixes, `DESTDIR`, and escaped strings. The OpenCDM `.pc` file derives its prefix from `${pcfiledir}/../..`.

Build-provided paths may now be relative. OpenCDM's integration tests previously passed a relative fixture path to an absolute-only API, which crashed in ReleaseFast. The loader now accepts either form:

```zig
// Before
std.Io.Dir.openFileAbsolute(testing.io, fixture_path, .{})

// After
std.Io.Dir.cwd().openFile(testing.io, fixture_path, .{})
```

Bench's integration and clean-room helpers resolve fixture/default/staging paths against the recorded build root before changing child process environments.

Zenith now requires Zig 0.17, ships matching Wayland/translate-c archives, and seeds the source-vendored FreeType wrapper directly. This replaces edits to opaque Zig package-cache directories. Browser CI downloads 0.17.0 and checks its updated SHA-256.

## Runtime compatibility fixes

Linux `waitpid`/`wait4` status storage is now `i32`. Consumers using unsigned status macros explicitly reinterpret the status bits.

```zig
// Before
var status: u32 = 0;
_ = linux.wait4(pid, &status, 0, null);

// After
var status: i32 = 0;
_ = linux.wait4(pid, &status, 0, null);
const exited = linux.W.IFEXITED(@bitCast(status));
```

The updated zeit dependency changed clock construction in bar, lockscreen, and greeter:

```zig
// Before
zeit.instant(io, .{ .timezone = tz }) catch return null

// After
zeit.instant(.{ .now = io }, tz)
```

Bench's seeded CRC32C fallback could not be fixed with a rename alone: the new optimized alias has a different internal seed representation. The fallback now selects `std.hash.crc.Generic(u32, ...)` with the Castagnoli polynomial, reflected input/output, and `0xffffffff` initial/final XOR. Existing seeded and hardware/software comparison tests verify wire-compatible results.

## Terminal and dependency updates

Ghostty's Zig 0.17 branch changes PTY writes to ordinary byte slices, requires an allocator for palette updates, and makes clipboard acknowledgement explicit. Otter retains its callback status API and translates each result into Ghostty's new reply operation.

```zig
// Before
return cb(inner.handle(), inner.callbacks.userdata, &write);

// After, showing the success and denial cases
write.reply(switch (cb(inner.handle(), inner.callbacks.userdata, &write)) {
    .success => .{ .success = .{} },
    .denied => .denied,
    // Other existing statuses are mapped explicitly too.
});
```

Terminal regression tests check successful and denied OSC 5522 acknowledgements. Palette updates now use `try palette.changeDefault(core_allocator, colors)` so allocation failures propagate.

## New Ghostty features exposed by Otter

Relative Kitty placements now resolve through Ghostty's parent chain instead of being omitted. Otter handles pinned or Unicode-placeholder parents, signed cell offsets, pixel offsets, scrolling, resizing, deletion, and transparent overlap. Chain validation and lifetime remain owned by Ghostty.

```text
Before: image placement with P=<parent-image>,Q=<parent-placement> was skipped.
After:  P=1,Q=10,H=2,V=1 places a child two cells right and one row down
        from that parent; later scrolling/resizing moves both together.
```

OSC 7501 program status now updates tab labels and the window title. Each terminal owns up to 64 records, inherits app names from ancestor IDs, clears subtrees on request, and expires working/blocked state at the next primary prompt. Done/error records survive until replaced or cleared. A full reset clears all records. Text passes through title sanitization, including invisible formatting controls.

```sh
# Before: ignored by Otter's UI.
printf '\033]7501;state=working:app=build:progress=42\007'
# After: label begins "[working 42%] build: ..."

printf '\033]7501;state=blocked:kind=permission:app=build:msg=QXBwcm92ZQ==\007'
# After: label includes "[blocked:permission] build: ... — Approve"

printf '\033]7501;state=clear\007'
# After: ordinary shell title returns.
```

Other integrations found during the Ghostty review:

| Protocol | Before | After |
| --- | --- | --- |
| OSC 9;4 progress | Parser support without Otter status UI | Working/error/paused status appears until the first OSC 7501 report after reset |
| XTGETTCAP `TN` | Configured terminal name was absent | Query replies with the session's configured `TERM`, such as `xterm-256color` |
| XTVERSION / `TERM_PROGRAM_VERSION` | Hardcoded `0.11.70` / `0.1.0` | Both use the package manifest version, `0.12.0` in this train |
| Overlapping Kitty images | Any overlap could suppress an entire older image | Placements composite by z, image ID and placement ID, preserving uncovered pixels and alpha |

A second overlap regression used parent image `i=1,p=9` and child image `i=2,p=2` at equal z. Before the ordering fix, the real Wayland buffer contained 4,224 red parent pixels and zero child-blend pixels; the parent covered the child. The corrected order passes the same end-to-end assertion.

The new PTY-to-pixel integration test drives a real `/bin/sh` child, feeds its escape sequences through the terminal parser, and checks rendered pixels, chained placement, alpha overlap, and deletion. An isolated Wayland end-to-end test also verifies working/blocked/cleared window titles, alpha compositing in client SHM, and repaint after deleting the parent. Additional protocol tests cover fragmented input, feature-query replies, resets, capacity, session isolation, placeholder parents, and extreme offsets. The [rendered protocol fixture](../otter-term/testdata/visual/current/protocols@1x.png) was visually inspected.

Added profiling scenarios measured 24.5 µs per pinned-relative draw and 8.4 µs per placeholder-relative draw in this run. These are workload-specific smoke measurements, not a controlled performance comparison. Placeholder origins are scanned once per graphics pass and cached for children in that pass.

## Verification

Validation ran on Linux x86_64 with Zig 0.17.0 and `-Doptimize=ReleaseFast`. Caches and install prefixes were redirected to `/tmp/otter-zig-017` because the workspace filesystem was nearly full. ## Existing limits and unverified environments

- The wider vendored uucode suite still has 18 failing lookup tests. An untouched checkout tested with Zig 0.16.0 has 19 failures; every 0.17 failure also appears in that baseline. The production-selected bidi fields and itijah suite pass. This migration does not repair those unrelated upstream lookup failures.
- Optional bidi differential checks report 48 differences against FriBidi on 158 cases; ICU agrees on 157, with one warning. The differential command's successful exit is not an exact-equivalence claim.
- zhl's upstream release gates require external grammar-corpus tooling and also report an existing file-length violation. The added `test-unit` target exercises its bundled tests without those upstream release gates.
- No live GPU recording, audio hardware, root service installation, other CPU architectures, full Debian package train, or Zig 0.16-versus-0.17 performance comparison was run. Existing headless gates also report their unavailable scenarios explicitly.
- Release completion and package-build evidence are recorded below as each publication stage finishes.
